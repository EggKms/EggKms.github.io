오늘은 Codex와 함께 게임 개발을 시작한 첫날이다.

아직 게임의 장르도, 플레이어가 무엇을 하게 될지도 정하지 않았다. 대신 앞으로 오랫동안 게임을 만들어 갈 수 있도록 프로젝트의 뼈대와 작업 원칙부터 세웠다.

당장 눈에 보이는 콘텐츠는 많지 않지만, 나에게는 꽤 기념비적인 출발이다.

## 실행 가능한 Godot 프로젝트 만들기

첫 번째 목표는 문서만 있는 저장소가 아니라 실제로 실행하고 검증할 수 있는 프로젝트를 만드는 것이었다.

현재 프로젝트의 기술 기준은 다음과 같다.

- Godot 4.7.2
- GDScript
- GL Compatibility 렌더러
- Windows용 Steam 게임 출시 목표

`Main` 장면 아래에 게임 월드와 UI가 들어갈 기본 구조를 만들었다. 아직 실제 게임플레이는 없지만 프로젝트를 실행할 수 있고, 자동화된 스모크 테스트에서 메인 장면을 불러와 인스턴스화할 수 있다.

장기적으로는 2560×1440 QHD를 목표 화질로 삼고 1920×1080 FHD를 필수 지원 해상도에 포함하기로 했다. 실제 실행 시에는 사용자의 디스플레이 환경에 맞게 비례 표시하고, 해상도와 화면 모드를 직접 선택하는 옵션은 게임 설정 기능을 구현할 때 추가할 예정이다.

## 게임보다 먼저 만든 개발 기준

오늘 가장 많은 시간을 들인 부분은 앞으로의 개발 방향을 문서로 정리하는 일이었다.

저장소에는 다음 기준이 들어갔다.

- 기능별로 장면, 스크립트, 리소스를 가까이 배치한다.
- 깊은 상속보다 컴포지션을 우선한다.
- 독립적인 장면 사이에서는 signal을 우선한다.
- 실제 사용 사례가 생기기 전에 범용 프레임워크를 만들지 않는다.
- 작은 수직 기능 단위를 구현하고 검증하는 방식으로 진행한다.
- 코드와 문서가 달라지면 같은 작업에서 함께 수정한다.

단순히 코드를 작성하는 것뿐 아니라 왜 그런 선택을 했는지, 무엇을 검증했는지까지 저장소 안에 남길 수 있도록 실행 계획과 결정 기록의 형식도 준비했다.

## Codex와 협업하는 방법

Codex가 모든 결정을 대신 내리는 방식이 아니라, 진행 가능한 기술적 세부사항은 자율적으로 처리하고 중요한 제품 결정은 나와 함께 정하도록 경계를 세웠다.

특히 문서에서 두 가지 상태를 구분한다.

- `결정 필요`: 게임의 방향이나 제품 판단처럼 내가 선택해야 하는 항목
- `검증 필요`: 구현, 실행 또는 테스트를 통해 사실을 확인해야 하는 항목

기본적으로 하나의 메인 에이전트가 조사부터 구현, 문서화와 최종 검증까지 책임진다. 작업을 여러 개로 나누는 것이 실제로 유리할 때만 보조 에이전트를 사용하도록 했다.

커밋과 푸시처럼 Git 이력이나 외부 저장소에 영향을 주는 작업은 내가 명시적으로 요청할 때만 수행한다.

## Steam, MOD, 다국어를 위한 경계

최종 목표는 Windows용 Steam 게임 출시다. 그러나 아직 게임의 핵심도 정하지 않은 상태에서 Steamworks 기능부터 연결하지는 않기로 했다.

핵심 게임 규칙은 Steam API 없이도 실행하고 테스트할 수 있게 유지하고, 나중에 플랫폼 기능이 필요해지면 교체 가능한 어댑터 경계 뒤에 배치한다.

MOD는 데이터 중심 확장을 기본 방향으로 삼았다. 외부 스크립트 실행은 보안과 유지 비용을 별도로 검토하기 전까지 허용하지 않는다.

다국어 지원도 미리 완성하려는 것이 아니라, 나중에 되돌리기 어려운 경계부터 보호한다. 플레이어에게 보이는 문구와 게임 내부 식별자를 분리하고, UI는 번역에 따라 문자열 길이가 달라질 수 있다는 점을 고려한다.

아직 Steamworks SDK, MOD 로더, 번역 리소스를 구현한 것은 아니다. 오늘은 미래의 가능성을 과도하게 구현하지 않으면서도 잘못된 결합을 피할 수 있는 기준을 만든 날이다.

## 오늘의 검증 결과

프로젝트의 표준 전체 검사를 실행했다.

검증 결과는 다음과 같다.

- 저장소 구조와 필수 문서 검사 통과
- Godot 4.7.2 실행 파일 확인
- 프로젝트 리소스 가져오기 통과
- GDScript 파일 2개 구문 검사 통과
- 메인 장면 로드 및 인스턴스화 스모크 테스트 통과
- 전체 프로젝트 검사 통과

오늘 변경은 프로젝트 기반과 문서 중심이어서 실제 게임 조작에 대한 플레이테스트는 아직 대상이 아니다.

QHD와 FHD 지원은 장기 목표다. 실제 화면과 UI를 해당 해상도에서 플레이테스트하기 전까지는 `검증 필요` 상태로 남긴다.

## 아직 정하지 않은 것

게임의 중요한 부분은 이제부터 함께 결정해야 한다.

- 어떤 장르의 게임인가?
- 플레이어는 누구이며 무엇을 하는가?
- 첫 번째로 검증할 재미는 무엇인가?
- 첫 수직 기능 단위는 어디까지인가?
- 첫 출시에서 어떤 언어와 입력 장치를 지원할 것인가?

이 질문들을 성급하게 확정하지 않고 `결정 필요` 상태로 남겨 두었다.

## 다음 단계

다음 작업은 거대한 시스템을 미리 만드는 것이 아니다.

게임을 한 문장으로 설명하고, 짧은 플레이 안에서 시작부터 결과까지 경험할 수 있는 첫 번째 수직 기능 단위를 정할 것이다. 그리고 그 기능을 실제로 구현하고 플레이하면서 재미를 확인할 계획이다.

오늘 만든 것은 게임의 완성본이 아니다. 하지만 앞으로의 모든 작업을 안전하게 쌓을 수 있는 첫 번째 기반이다.
