8월 28일과 29일, 이틀 동안 게임은 빈 프로젝트에 가까운 상태에서 전선이 움직이고 보급로가 끊기는 전략게임 프로토타입으로 바뀌었다.

이번에 만들고 있는 게임은 헥스 맵 위에서 개별 병사를 직접 조종하는 게임이 아니다. 플레이어는 군단 HQ의 위치를 정하고, 시스템은 그 위치를 바탕으로 주변 전선에 병력을 자동으로 배분한다. 전력을 집중해 돌파구를 만들고, 그 틈으로 적의 보급망을 끊는 실시간 전략 보드게임을 목표로 한다.

한 문장으로 줄이면 이렇다.

> 군단의 위치가 곧 명령이 되는 게임.

이번 이틀의 목표는 이 문장이 실제 게임 규칙으로 이어질 수 있는지 확인하는 것이었다.

## 8월 28일: 전장이 생기고 군단을 움직이다

첫 작업은 앞으로의 모든 거리, 전선, 이동과 보급 계산이 올라갈 헥스 맵을 만드는 일이었다.

### 70개의 헥스로 만든 첫 전장

10×7 크기의 테스트 맵에 총 70개의 헥스를 만들었다. 맵은 플레이어와 적의 영토로 절반씩 나뉘며 양쪽에 수도가 하나씩 있다.

화면에 육각형을 그리는 것만으로 끝내지 않았다. 헥스의 좌표와 인접 관계를 계산하는 규칙을 화면 표현과 분리했다.

- 축 좌표 기반의 헥스 위치
- 여섯 방향 인접 헥스 계산
- 두 지점 사이의 Hex Distance
- 아군 영토 안에서의 최단경로
- 헥스 좌표와 화면 픽셀 위치의 양방향 변환

이 분리 덕분에 앞으로 추가될 군단 이동, 전선 탐지와 보급 경로를 화면 없이도 자동 테스트할 수 있게 됐다.

플레이어 영토는 파란색과 세로 문양, 적 영토는 붉은색과 가로 문양으로 표시했다. 수도에는 노란 마름모를 더했다. 색만으로 정보를 구분하지 않는 원칙을 첫 화면부터 적용한 것이다.

### 군단 HQ가 플레이어의 명령이 되다

다음으로 양측에 군단 HQ를 5개씩 배치했다.

플레이어는 아군 HQ를 선택하고 아군 영토의 목적지를 한 번 클릭한다. 그러면 군단은 아군 영토 안의 최단경로를 찾아 인접 헥스씩 이동한다. 적 영토나 맵 밖을 클릭하면 이동하지 않는다.

선택한 군단에는 금색 이중 외곽선을 표시하고, 현재 위치를 기준으로 Hex Distance 2의 영향 범위를 보여 준다. 군단이 이동하는 동안에도 실제로 도착한 헥스를 기준으로 영향 범위가 갱신된다.

이때부터 플레이어의 핵심 행동이 처음으로 화면에 나타났다.

```text
군단 선택 → 목적지 지정 → 자동 이동 → 영향 범위 변화
```

아직 전투는 없었지만 “어디에 군단을 둘 것인가”라는 판단을 조작으로 옮길 수 있게 됐다.

### 전체 설계와 Stage 1을 분리하다

기능을 만드는 중간에 게임 디자인 문서도 다시 나눴다.

전체 게임이 지켜야 할 장기 규칙과, 첫 프로토타입에서만 사용하는 임시 수치가 한 문서에 섞이면 테스트값이 확정 규칙처럼 굳어질 수 있다. 그래서 전체 게임 디자인과 Stage 1 명세를 분리했다.

예를 들어 10×7 맵, 영향 거리 2, 헥스당 0.25초 이동은 현재 프로토타입을 빠르게 검증하기 위한 값이다. 실제 플레이가 재미있는지 확인하기 전까지 최종 규칙으로 확정하지 않는다.

8월 28일이 끝났을 때는 전장이 생겼고, 군단을 선택해 이동시킬 수 있었다.

## 8월 29일: 군단의 위치가 전선을 움직이기 시작하다

둘째 날에는 군단의 위치를 자동 전선, 병력 배분, 전투와 보급으로 차례로 연결했다.

### 접촉한 영토에서 전선을 자동으로 찾다

서로 다른 진영의 헥스가 맞닿은 변을 찾아 양측의 전선을 자동으로 구성했다.

각 군단은 자신의 영향 범위 안에 있는 같은 진영 전선을 지원한다. 여러 전선을 지원할 때는 현재 가진 병력을 균등하게 나눈다. 한 군단이 병력 100을 세 전선에 제공한다면 각 전선에 약 33.3씩 배분하는 방식이다.

여러 군단의 영향 범위가 같은 전선에 겹치면 제공 병력이 합산된다. HQ가 다른 헥스에 도착하거나 영토의 소유권이 바뀌면 전선과 병력 배분도 즉시 다시 계산한다.

```text
HQ 위치
  ↓
영향 범위 안의 아군 전선 탐색
  ↓
군단 병력 자동 분배
  ↓
전선별 제공 병력 합산
```

이 단계에서 “위치가 곧 명령”이라는 설계가 단순한 문구를 넘어 실제 규칙이 됐다. 플레이어가 전선마다 병력을 몇 명 보낼지 지정하지 않아도, 군단의 위치만 바꾸면 전선 전체의 병력 분포가 달라진다.

### 병력을 쌓되 무한히 강해지지는 않게 하다

여러 군단을 한곳에 모으는 전략에는 이점이 있어야 하지만, 한 전선에 모든 군단을 쌓는 것이 언제나 정답이어서는 안 된다.

이를 확인하기 위해 전선 수용량을 넣었다. 현재 테스트값은 전선당 50이다.

- 제공 병력이 수용량 이하이면 전부 실제 전투에 참여한다.
- 수용량을 넘은 병력은 예비 병력으로 남는다.
- 전투 손실이 생기면 예비 병력이 다음 계산에서 실전 병력을 보충한다.

화면에서는 첫 줄에 실제 전투 병력, 둘째 줄에 `R`을 붙인 예비 병력을 표시한다. 수용량을 초과한 전선에는 노란 테두리도 추가했다.

전력 집중은 돌파 가능성을 만들지만, 수용량을 넘긴 병력은 즉시 전투력을 무한히 높이지 않는다. 다른 전선을 비워 가며 더 많은 군단을 한곳에 보낼 가치가 있는지 판단하게 만드는 장치다.

### 전투가 자동으로 진행되고 영토가 바뀌다

다음 단계에서는 맞닿은 전선의 실제 전투 병력을 비교해 자동 전투를 진행하도록 했다.

한 전선 헥스가 여러 적 헥스와 접촉하면 병력을 접촉 수로 나눈 뒤, 각 접촉 변에서 전력비를 계산한다. 양측 모두 피해를 입지만 열세인 쪽이 더 큰 피해를 받는다. 우세가 계속되면 압박 수치가 누적되고, 임계치에 도달한 쪽이 상대 헥스를 점령한다.

영토가 바뀌면 다음 정보가 한 흐름 안에서 즉시 다시 계산된다.

- 새 영토 소유권
- 새로 형성되거나 사라진 전선
- 군단별 지원 대상
- 실제 전투 병력과 예비 병력
- 계속 유효한 전투 접촉과 압박

현재 테스트에서는 2:1 우세가 지속되면 약 10~20초 안에 한 헥스를 점령하는 체감을 목표로 했다. 피해율, 압박 속도와 점령 임계치는 모두 플레이테스트를 위한 초기값이지 최종 전투 공식은 아니다.

화면에는 우세 진영, 전력비, 압박 수치와 방향 화살표를 함께 표시해 영토가 왜 움직이는지 추적할 수 있게 했다.

### 보급로를 끊으면 전투력이 절반으로 떨어지다

마지막으로 이번 게임의 핵심 목표인 보급을 전투에 연결했다.

각 진영의 수도를 고정 보급원으로 두고, 수도에서 군단 HQ까지 아군 영토만 지나는 BFS 최단경로를 찾는다. 경로가 존재하면 정상 보급, 존재하지 않으면 보급 차단 상태다.

정상 보급 상태의 군단은 전투 효율 100%를 유지한다. 경로가 끊기는 순간에는 50%로 떨어진다. 이 효율은 전선 수용량을 적용한 뒤의 실제 전투 병력에 반영된다. 예를 들어 실제 전투 병력이 50인 군단이 보급 차단 상태가 되면 유효 전투력은 25가 된다.

보급의 원인과 결과를 한 화면에서 읽을 수 있도록 다음 피드백도 추가했다.

- 플레이어 보급로는 실선, 적 보급로는 점선
- 선택한 군단의 경로는 굵은 금색 선
- `S` 키로 양측 보급로 오버레이 전환
- 정상 상태는 연결된 고리, 차단 상태는 끊어진 고리
- 마지막 정상 경로는 붉은 점선으로 보존
- 빼앗긴 경로 헥스에는 `X` 표시
- 차단 순간 `보급 차단` 문구 표시

기존 경로가 끊겨도 다른 아군 경로가 남아 있다면 같은 틱에 우회 경로를 다시 찾는다. 화면에 보이는 길과 실제 보급 판정이 서로 어긋나지 않도록 판정과 표시를 함께 갱신한다.

군단 이동에도 작은 비용을 넣었다. 목적지에 도착한 군단은 기본 3초 동안 `전개 중` 상태가 되어 전선을 지원하지 않는다. 위치를 바꾸는 결정이 즉시 무료로 전투력만 옮기는 행동이 되지 않게 하기 위한 첫 테스트다.

## 이틀 동안 완성된 첫 번째 전략의 흐름

28일 아침에는 전선도 군단도 없었다. 29일 밤에는 다음 흐름이 한 장면 안에서 이어졌다.

```text
전장 관찰
→ 군단 HQ 재배치
→ 지원 전선과 병력 자동 분배 변화
→ 국소적 병력 집중
→ 자동 전투와 돌파
→ 영토 변화
→ 적 보급로 차단
→ 적 군단의 유효 전투력 감소
→ 다시 전선 재계산
```

Stage 1은 총 아홉 개 테스트케이스로 계획했다. 이번 이틀 동안 TC-01 헥스 맵부터 TC-06 보급까지 완료했다. 아직 한 판의 시작과 종료는 없지만, 게임의 핵심 인과관계는 처음부터 끝까지 연결된 셈이다.

## 자동 검사와 화면 검증

기능을 하나 추가할 때마다 이전 규칙이 깨지지 않는지 전체 검사를 다시 실행했다.

최종 상태의 검증 결과는 다음과 같다.

- Godot 4.7.2에서 프로젝트 리소스 가져오기 통과
- GDScript 26개 구문 검사 통과
- 헥스 거리·인접·경로와 소유권 규칙 테스트 통과
- 군단 선택·이동·영향 범위와 실제 입력 통합 테스트 통과
- 자동 전선·병력 분배·수용량·예비 병력 테스트 통과
- 전투 피해·압박·점령과 영토 변경 통합 테스트 통과
- 보급 단절·우회·회복과 전투 효율 반영 테스트 통과
- 메인 장면 스모크 테스트 통과
- Windows/OpenGL 3의 1280×720 화면에서 각 단계의 시각 확인 완료

모델과 화면 표현을 분리해 규칙은 자동 테스트하고, 실제 화면에서는 문양·선·기호·숫자가 서로 겹치지 않고 읽히는지 확인했다.

## 아직 검증해야 할 재미

기능이 동작한다는 것과 게임이 재미있다는 것은 다르다.

아직 실제 플레이어와 확인해야 할 질문이 남아 있다.

- 군단 HQ만 움직여도 충분한 통제감을 느끼는가?
- 자동 병력 분배의 결과를 쉽게 이해할 수 있는가?
- 0.25초 이동과 도착 후 3초 전개가 전략적 비용으로 느껴지는가?
- 플레이어가 정면 공격 대신 우회와 보급 차단을 선택하는가?
- 보급로가 바뀌었을 때 우회 경로를 자연스럽게 이해하는가?
- 병력을 직접 움직이지 않았는데도 내 전략으로 전선이 무너졌다고 느끼는가?

현재의 수치와 UI는 이 질문에 답하기 위한 프로토타입이다. 테스트 결과에 따라 맵 배치, 이동 속도, 병력 분배, 전선 수용량, 전투 공식과 보급 효과는 달라질 수 있다.

## 다음 단계

다음 테스트케이스는 `TC-07 게임 흐름`이다.

적 수도를 점령하면 승리하고 아군 수도를 잃으면 패배하도록 만들 예정이다. Pause, 1배속·2배속, 재시작도 추가해 한 판을 시작하고 진행하고 끝낼 수 있는 흐름을 완성한다.

그 뒤에는 교착에서 돌파와 보급 차단으로 이어지는 상황을 의도적으로 만들 수 있도록 Stage 1 전용 테스트 맵을 다듬고, 수치를 빠르게 조정할 디버그 도구를 준비할 계획이다.

이틀 전에는 “군단의 위치가 곧 명령”이라는 문장만 있었다.

지금은 군단을 옮기면 전선의 병력이 달라지고, 전투가 진행되고, 영토가 움직이고, 끊어진 보급로가 적 전선 전체를 약화시킨다.

아직 게임 한 판은 완성되지 않았다. 하지만 무엇을 재미로 검증해야 하는 게임인지는 이제 화면 위에서 움직이기 시작했다.
